# Attn-Experts MoE: маршрутизация механизмов внимания по токенам

*(English version: [README_EN.md](README_EN.md))*

Исследовательский каркас вокруг одной идеи (формулировка автора проекта):
**под каждый токен собирать свою экспозицию вниманий из пула разных
разреженных механизмов** -- роутер сам решает, какой тип смешивания нужен
этому токену: точное окно, top-k прыжки, линейную память или бюджетные
проекции. Поверх этого выстроены три развития: иерархия «дёшево → выбор →
уточнение», роутер, читающий дешёвую проекцию контекста, и выборочная
дорогая доработка.

## TL;DR главные результаты

| эксперимент | результат |
|---|---|
| Копирование, пул 2 окна+2 линейных, роутер с проекцией | **1.90** против 2.00 у однородного пула |
| Смешанная нагрузка (копирование+мода), роутер с проекцией | **2.136** -- лучший на ОБЕИХ подзадачах сразу |
| Иерархическое внимание на копировании T=128 | **2.52** при **33%** открытых ключей (плотное 2.59/100%) |
| Старт обучения против JetMoE-стиля | заметно быстрее при равном бюджете |
| Активные параметры на токен | в ~3.4 раза меньше полного пула |

Честный вердикт: как замена обычному вниманию «здесь и сейчас» -- нет
(плотное точнее на равном бюджете и быстрее на игрушке). Ценность --
в подтверждённой механике специализации и в экономии вычислений,
которая конвертируется в выигрыш при масштабе и блочных кернелах.

## Как устроено «внимание автора проекта» (ядро системы)

Это не один модуль, а способ сборки слоя. Поток данных:

1. **Пул экспертов** (`src/experts.py`, фабрики `make_attn_pool` /
   `make_ffn_pool`): несколько независимых блоков внимания разных видов --
   `AttentionExpert` с паттернами `window` / `topk` / `dense`
   (свои Wq/Wk/Wv/Wo), `LinearAttentionExpert` (линейное внимание,
   родня DeltaNet: состояние S_t = Σ φk⊗v, выход φq·S_t, нормировка
   знаменателем) и `ProjectionMoEAttention` (JetMoE-стиль, общее ядро).
2. **Роутер** (`src/router.py`, `TopKRouter`): для каждого токена считает
   скоры всех экспертов и берёт top-k; есть два режима -- обычный
   uniform top-k и **типовые квоты** (`typed_ks`: ровно k_ffn + k_attn),
   плюс балансирующая aux-потеря и z-loss.
3. **Диспетчер** (`src/moe.py`, `SparseMoE`): назначения сортируются по id
   эксперта, образуя сплошные куски -- один GEMM на эксперта, одна запись
   обратно через `index_put_/index_add_`, один host-sync на слой.
4. **Сборка**: выходы выбранных экспертов взвешиваются гейтами и
   складываются в residual. Блоки -- `DualMoEBlock`
   (`src/block.py`): режим `sequential` (внимание-пул + FFN-пул) и
   `mixed` (общий пул с типовыми квотами).

То есть «ваше внимание» -- это шаги 1--4: оно присутствует во всех
экспериментах ниже как слой `attn`; виды экспертов задаются строкой
(`--kinds window,topk,linear`), а роутер выбирает между ними **по токенам**.

## Развитие 1: смесь механизмов и её главный подводный камень

Первый вариант `LinearAttentionExpert` не имел нормировки состояния: выход
раздувался до величины ~7310 против ~0.4 у оконных и заглушал всю смесь
(диагностика `exp_routing.py`). Лечение -- знаменательная нормировка, как в
Katharopoulos/RetNet. После фикса:

| пул (копирование, 400 шагов) | CE |
|---|---|
| 4 окна | 2.00 |
| окна+линейные до фикса | 2.62 |
| окна+линейные после фикса | **1.90** |

Диагностика роутера показала также локальное равновесие: без внешней
подсказки он держит ~50% нагрузки на каждом типе, даже когда один объективно
лучше (и это не aux-потеря -- проверено отключением). Поведенческий тест
(`test_router_learns_to_prefer_capable_expert`) фиксирует границу: явную
разницу способностей роутер осваивает.

## Развитие 2 (v1): роутер видит дешёвую проекцию контекста

Идея обсуждения: дать гейту грубый «снимок» всего прошлого. Реализация:
каузальное бегущее среднее спроецированных токенов конкатенируется с
признаками на входе гейта (`proj_router`, `SparseMoE._causal_ctx`).

Бенчмарк разнородной нагрузки `exp_mixedtask.py` -- поток 50/50 из
копирования (работа окон) и слежения за модой префикса (работа линейной
памяти), 400 шагов:

| конфиг | CE общая | копия | мода | доля линейных |
|---|---|---|---|---|
| 4 окна | 2.344 | 2.168 | 2.556 | -- |
| окна+линейные | 2.391 | 2.485 | 2.380 | 56% |
| **окна+линейные + проекция в роутере** | **2.136** | **2.107** | **2.126** | 47% |

Проекция снимает трейд-офф специализации: без неё пул выигрывает только на
одной подзадаче, с ней -- на обеих сразу. Первый положительный ответ на риск
«равновесия роутера».

## Развитие 3: иерархическое «дёшево → выбор → уточнение»

Прототип `src/hier.py`: лендмарки по блокам (дешёвая проекция) → поточный
строго каузальный гейт выбирает top-k прошлых блоков → точное внимание
только к ним + петля уточнения с фиксированным V (K/V один раз, Q
пересчитывается). Тесты ловят три канала утечки будущего через гейт.

Копирование T=128 (дистанция 65), 600 шагов:

| внимание | CE | открытых блоков |
|---|---|---|
| плотное | 2.59 | 100% |
| иерархическое | **2.52** | **33%** |

Оговорка: стеночное время не экономится -- маска подаётся в плотный SDPA;
нужен блочно-разреженный кернел.

## Развитие 4 (v2): дорогое уточнение только там, где выбрано

Гейт блока (`attn_select_frac`) оставляет долю токенов по правилу
«растущего бюджета» (токен берётся, если входит в топ-долю СВОЕГО префикса
-- глобальный top-k недопустим, он зависит от будущих скоров). Пул внимания
считает только выбранные строки: оконные/top-k эксперты идут точным путём
`forward_selected` (реальная экономия FLOPs ∝ доле), линейные всё равно
сканируют всё (они дешёвые). Мягкий сигмоид-вес проводит градиент в гейт
выбора. Сводка на разнородной нагрузке (400 шагов):

| конфиг | уточнение | CE общая | копия | мода |
|---|---|---|---|---|
| окна (однородный) | 100% токенов | 2.344 | 2.168 | 2.556 |
| смешанный | 100% | 2.391 | 2.485 | 2.380 |
| **v1: + проекция в роутере** | 100% | 2.136 | 2.107 | 2.126 |
| **v2: v1 + бюджет 60% токенов** | **60%** | **2.050** | 2.262 | **1.876** |
| v2: v1 + бюджет 35% | 35% | 2.390 | 2.651 | 2.167 |

Главная находка: **бюджет 60% улучшает общее качество при 40% экономии
внимания** -- ограниченный выбор уточнений работает как регуляризация и
заставляет роутер быть разборчивее. Слишком тесный бюджет (35%) режет по
живому.

## Честные ограничения

* Игрушечный масштаб (d≤128, ≤4 слоя, один-два сида); стеночное время на
  общей GPU не показатель.
* Экономия вычислений пока структурная/аналитическая: без блочно-разреженных
  кернелов wall-clock не выигрывает.
* Равновесие роутера смягчается проекцией, но не решено в общем случае.
* Линейный эксперт -- упрощённый DeltaNet без затухания/gating.

## Близкие работы и где новизна

Занятые ниши: MoA/SwitchHead/JetMoE (MoE в внимании); NSA/MoBA/Routing
Transformer/Landmark/Informer (иерархический выбор блоков); Jamba/Zamba/
Samba/Griffin/Hymba (гибриды внимание+SSM с жёстким расписанием);
Mixture-of-Depths (роутинг глубины).

Свободное пересечение, к которому ведёт этот код: **гетерогенное
иерархическое внимание -- per-token маршрутизация МЕЖДУ механизмами
(окна/top-k/DeltaNet/проекции), управляемая дешёвой проекцией контекста**.
Куски по отдельности известны; их сочетание в литературе не найдено.

## Воспроизведение

```bash
python3 tests/test_all.py            # 17 тестов механики и поведения
python3 tests/test_hier.py           # 5 тестов иерархического внимания
python3 train_demo.py --steps 400    # копирование: однородный vs смешанный пул
python3 train_lm.py                  # Shakespeare char-LM сравнение
python3 exp_routing.py               # диагностика равновесия роутера
python3 exp_mixedtask.py             # v1: разнородная нагрузка (+ --select-frac)
python3 exp_hier.py                  # иерархическое против плотного
```

Ветка `hier-refine-attention`; базовый коммит каркаса на `master`.
