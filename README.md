# Attn-Experts MoE: маршрутизация механизмов внимания по токенам

*(English version: [README_EN.md](README_EN.md))*

Идея проекта (авторская): **для каждого токена собирать свою экспозицию
вниманий из пула разных разреженных механизмов** — роутер решает, что
нужно этому токену: точное окно, быструю память, длинную память или
прыжки. Проект — путь от прототипа до рабочей архитектуры, где каждое
решение проверено контрольным экспериментом.

## Итоговая архитектура (hybrid100) — главная

Лучший результат проекта: **CE 1.874 против 2.344 у плотных окон — минус
20% ошибки** на разнородной нагрузке (копирование через разделитель +
слежение за модой), лучший худший случай по подзадачам. Сборка: один
конструктор — `src/best.py::make_hybrid100`, демо — `best_demo.py`.

```
x ──► LayerNorm ──► ПУЛ МЕХАНИЗМОВ ВНИМАНИЯ (top-2 из 4, роутер) ──► +x
                      окно 72   — точный локальный поиск
                      lin9      — линейное внимание, γ=0.9  (~10 шагов)
                      lin99     — линейное внимание, γ=0.99 (~100 шагов)
                      linL      — γ обучаемый (сходится к ~0.985–0.99)
          роутер видит [токен ; каузальное бегущее среднее проекций
          прошлого] — дешёвый снимок всего контекста
 далее: FFN-MoE (top-2 из 8) ──► +residual     (обычная часть блока)
```

Каждое решение оплачено экспериментом:

| решение | зачем | что без него |
|---|---|---|
| топ-2 из гетерогенного пула | разным задачам — разные механизмы | окна: 2.344 |
| проекция прошлого в роутере | роутер видит тип задачи, а не только токен | 2.136 и равновесие 50/50 |
| горизонты памяти + обучаемое затухание | равноценные механизмы: «память на шаг / на абзац» | 1.92–1.94 |
| нормировка выходов экспертов | без неё линейный даёт \|7310\| против 0.4 | смесь умирает |
| БЕЗ бюджета выбора (100% токенов) | на этом пуле бюджет вредит | 2.064 |

Выученный γ≈0.985–0.99 во всех прогонах — модель сама предпочитает
забывать, а не помнить вечно. Активных параметров на токен ~2.1M из
7.4M (**в 3.5 раза меньше** полного пула).

## Как это устроено (кратко)

* **Эксперты** (`src/experts.py`): `AttentionExpert` (окно/top-k/dense,
  свои Wq/Wk/Wv/Wo, точный путь для выбранных строк `forward_selected`),
  `LinearAttentionExpert` — линейное внимание (DeltaNet-родня) с затуханием:
  быстрый cumsum-путь, эквивалентный рекуррентности до 1e-7, и честный
  цикл; `ProjectionMoEAttention` (JetMoE-стиль).
* **Роутер** (`src/router.py::TopKRouter`): top-k с типизированными квотами,
  Switch-aux и z-loss; режим `proj_router` добавляет к признакам токена
  каузальное бегущее среднее проекций прошлого (`SparseMoE._causal_ctx`).
* **Диспетчер** (`src/moe.py::SparseMoE`): сортировка назначений → по одному
  GEMM на эксперта, одна синхронизация на слой; `forward_rows` считает
  дорогие эксперты только на выбранных строках.
* **Блок** (`src/block.py::DualMoEBlock`): attention-пул + FFN-пул,
  layouts `sequential` / `mixed`.

## Что проверено и не подтвердилось (честно)

1. **Роутер против жёсткого расписания.** При известном профиле задач
   расписание не хуже (и на копирование лучше). Роутер выигрывает
   устойчивостью к неизвестному профилю (худшая подзадача 2.03 против
   2.45) и побеждает в полной сборке при равноценных механизмах.
2. **Бюджет выбора (v2)**: на слабом пуле давал и качество, и экономию,
   но **не переносится** на сильный пул — регуляризация бюджетом
   оказалась свойством слабого пула, а не универсальным законом.
3. **Роутинговое равновесие**: без контекста роутер застревает на 50/50
   независимо от aux-лосса; проекция прошлого снимает проблему.
4. **Иерархический прототип** (`src/hier.py`): 2.52 при 33% ключей против
   2.59 у dense — механика работает, стеночной экономии нет без
   блочно-разреженных кернелов.

## Ограничения

Игрушечный масштаб (d=128, 4 слоя, по одному сиду); экономия структурная
(FLOPs), а не стеночное время — нужен блочно-разреженный кернел; линейный
эксперт — упрощённый DeltaNet без decay-гейтов на значениях; прогоны на
общей GPU, стеночное время не показательно.

## Близкие работы

MoA / SwitchHead / JetMoE (MoE внутри внимания); NSA / MoBA / Routing
Transformer / Landmark (иерархический выбор блоков); Jamba / Zamba /
Samba / Griffin / Hymba (гибриды внимание+SSM с фиксированным расписанием);
Mixture-of-Depths (маршрутизация глубины). Свободная ниша, к которой идёт
проект: **гетерогенное иерархическое внимание с маршрутизацией МЕЖДУ
механизмами по токену, управляемой дешёвой проекцией контекста**.
